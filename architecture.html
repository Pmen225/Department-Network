Azure network design

Shared networking and managed file storage for Estates, Finance and Operations in Azure UK South. Solid boxes show Terraform resources. Dashed boxes show the proposed printers. Dashed arrows show access paths that have not been configured or tested. These changes have not been applied.

File and printer access

VM clients access each department's file share through its storage account address. They connect to printers separately. Dashed arrows show intended client access; storage accounts do not send print jobs.

Design decisions

Shared subscription: keeps the network and department storage together. Separate storage accounts and department tags support cost tracking without extra subscriptions.

Network: separate subnets reserve addresses for VMs and printers. The VM subnet has a security group with default rules, which still allow traffic within the VNet. No custom access restrictions are configured. The printer subnet has no security group. The VM subnet uses a NAT gateway and static public IP for outbound connections.

Virtual machines: one Windows Server 2022 VM per department, each with a private address in the VM subnet. Each uses Standard_D2s_v4 and a Standard LRS system disk. No public VM addresses or remote access service are configured.

Password protection: the administrator password is supplied through a variable marked sensitive = true in both the root and Networking module. Terraform hides it in normal output. The setting does not encrypt the password or remove it from state and saved plans. Those files and local variable files are excluded from GitHub. See password security details.

Managed storage: Azure Files removes the need for a dedicated file-server VM. Each share uses the Hot tier for frequent access, a 500 GiB quota and Standard storage with geo-redundant replication.

File access: a client resolves the storage account name, connects over SMB on TCP port 445 and authenticates with permission to the share. The current configuration enables public storage endpoints and defines no private endpoints. A resource group organises resources; it does not connect them.

Private access option: a private endpoint would provide a private IP in the VNet for reaching the file service. It would also require DNS to resolve the storage name to that IP. This option is not configured.

Current status

Terraform validation and a live plan passed on 29 October 2026: 20 resources to add, none to change and one to destroy. The removal is the old printer-subnet NSG attachment. These changes have not been applied.

Microsoft Entra ID authentication, file-share permissions and a print service are not configured. The printer subnet alone does not provide printing.

The private DNS zone remains in Terraform and is omitted from these diagrams because its removal is planned. The resource group outputs all reference the first resource group. See design decisions and limitations.
